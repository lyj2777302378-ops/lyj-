# SnapVid 万能视频下载站 — 需求分析文档

> 版本：v1.0（2026-10-01）｜状态：第一期已实现核心闭环
> 用途：后续功能扩展时，供人与 AI 快速对齐需求背景与边界。

## 1. 项目背景与目标

很多用户有把视频保存到本地的需求，但现有渠道存在痛点：

| 痛点 | 说明 |
|---|---|
| 平台不支持下载 | 大量平台未开放下载入口 |
| 下载有限制 | 清晰度受限、需登录/会员、带水印 |
| 不支持批量 | 合集/播放列表只能逐个保存 |
| 跨端不便 | 手机上缺少好用的下载工具 |

**项目目标**：一个「粘贴链接 → 选清晰度 → 下载」的万能视频下载网站，PC 与手机浏览器均可使用，架构轻量、可快速迭代，并预留付费能力。

**项目性质**：学习型项目，核心目的是实践「AI 协作开发模式」。下载能力完全建立在开源项目 yt-dlp 之上，不自行逆向任何平台，不承担法律与封号风险。页面明确标注"仅供学习研究，请尊重版权"。

## 2. 目标用户

- 想离线保存公开视频的普通用户（学习资料、教程、素材收藏）
- 手机端用户（无 App 安装意愿，浏览器即用）
- （后续）愿意为高清画质、批量下载、AI 总结付费的重度用户

## 3. 功能需求

### 3.1 第一期（已实现）

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| F1 | 链接解析 | 粘贴视频链接，返回标题、封面、时长、来源平台、UP主 | P0 |
| F2 | 清晰度选择 | 展示可用清晰度档位（1080P/720P/…/仅音频），含文件大小预估 | P0 |
| F3 | 直接下载 | 平台提供直链时，浏览器直接走 CDN 下载（不占服务器带宽） | P0 |
| F4 | 中转下载 | 服务器用 yt-dlp 代下，流式回传给浏览器（兼容防盗链平台） | P0 |
| F5 | 进度反馈 | 中转下载时实时显示百分比、速度、剩余时间（SSE 推送） | P1 |
| F6 | 播放列表识别 | 合集链接展示条目列表，可逐个点击解析 | P1 |
| F7 | 移动端适配 | 响应式布局，手机浏览器可用 | P0 |
| F8 | 版权与隐私 | 服务器不留存文件（发送后即删 + 定期清理），页面展示免责声明 | P0 |
| F9 | VIP 占位 | 高清档（>720P）挂 VIP 角标，点击弹出升级弹窗（支付未接入） | P2 |

## 4. 非功能需求

- **轻量**：第一期无数据库，状态全在内存，重启即清零
- **安全**：不存储用户视频文件；不内置任何平台账号凭据；cookies 由用户自行提供
- **性能**：解析接口 < 10s（取决于平台响应）；中转下载边下边传，不做整文件缓存等待
- **合规**：页面显著位置展示版权免责声明；不建议面向公众大规模开放部署

## 5. 风险与边界

| 风险 | 应对 |
|---|---|
| 平台风控/反爬（如抖音、B站高清需登录） | 不硬刚，预留 cookies 入口（R6），由用户自带凭据 |
| 版权投诉 | 服务器不留存文件 + 免责声明 + 仅学习用途定位 |
| 服务器带宽压力 | 优先直链下载（F3），中转作为兜底；后续可加并发/限速 |
| yt-dlp 规则失效（平台改版） | pip 升级 yt-dlp 即可，业务代码零改动 |

## 6. 名词约定

- **解析（parse）**：调用 yt-dlp 提取视频元信息，不发生下载
- **直链（direct_url）**：平台 CDN 的临时文件地址，可能带防盗链（Referer 校验）
- **中转下载（relay）**：服务器代为下载再回传浏览器
- **selector**：yt-dlp 的格式选择表达式，如 `bestvideo[height<=720]+bestaudio/best`
