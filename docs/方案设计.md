# SnapVid 万能视频下载站 — 方案设计文档

> 版本：v1.0（2026-10-01）｜配套：《需求分析.md》
> 用途：后续扩展时供人与 AI 理解架构决策与接口契约，避免推倒重来。

## 1. 技术选型与决策理由

| 决策点 | 选择 | 理由 |
|---|---|---|
| 下载核心 | **yt-dlp**（pip 库调用，不改源码） | 18 万+ Star，支持 1000+ 站点；平台改版只需 `pip install -U yt-dlp`；风险由开源项目承担 |
| 后端框架 | **FastAPI + Uvicorn** | 与 yt-dlp 同为 Python 生态；异步支持好；自带 OpenAPI 文档（/docs） |
| 数据库 | **无（内存字典）** | 第一期最轻量；任务状态存活于进程内存，重启清零可接受 |
| 前端 | **原生 HTML/CSS/JS 单页** | 无需构建链，FastAPI 直接托管静态文件；手机/PC 响应式 |
| 进度推送 | **SSE（EventSource）** | 比 WebSocket 简单，单向推送足够 |
| ffmpeg | **imageio-ffmpeg** | pip 安装自带静态 ffmpeg 二进制，免用户手动装 ffmpeg（yt-dlp 合并音视频需要） |
| 部署形态 | 单进程 `python main.py`，监听 8000 | 局域网手机访问直接可用；公网部署自行加反向代理 |

## 2. 系统架构

```
┌────────────────────────────────────────────┐
│  浏览器（PC / 手机响应式）                    │
│  static/index.html + app.js + style.css    │
└──────┬───────────────────────┬─────────────┘
       │ POST /api/parse       │ 直链下载（浏览器 → 平台 CDN）
       ▼                       │
┌─────────────────────────┐   │
│  FastAPI (main.py)      │   │
│  ├─ /api/parse          │──► yt-dlp extract_info（只取元信息）
│  ├─ /api/download       │──► yt-dlp download（后台线程）
│  ├─ /api/progress/{id}  │──► SSE 轮询内存 TASKS 字典
│  ├─ /api/file/{id}      │──► FileResponse + 发送后删除
│  └─ /  静态文件托管      │
└──────────┬──────────────┘
           ▼
    downloads/ 临时目录（启动清空 + 发送即删 + 每小时巡检清理）
```

### 关键设计

1. **解析与下载分离**：`/api/parse` 只取元信息并生成清晰度选项（含 selector 表达式与直链候选），下载时才按 selector 真正拉流。避免一次请求做两遍重活。
2. **清晰度用 selector 表达式而非 format_id**：B站等平台的 format_id 会变，`bestvideo[height<=H]+bestaudio/best[height<=H]/best` 表达式更稳。
3. **直链优先、中转兜底**：解析时若存在"音视频合一"的格式则返回 `direct_url`，前端提供两个按钮让用户自选。防盗链平台（B站 CDN 校验 Referer）直链会失败，中转必成。
4. **任务模型**：`POST /api/download` 创建 task_id → 后台线程跑 yt-dlp，progress_hook 写入内存 `TASKS` → SSE 每 0.5s 推送 → 完成后前端拉 `/api/file/{id}`，文件发送后经 BackgroundTasks 删除。
5. **零留存**：启动清空 downloads/、文件发送后即删、后台 janitor 线程每 10 分钟清理超 1 小时的残留。
6. **风控平台对策**：项目根目录放 `cookies.txt`（Netscape 格式）即自动生效（yt-dlp cookiefile），代码已内置判断，用户自放自用。

## 4. 接口契约

### POST /api/parse
请求：`{"url": "https://..."}`
响应（单视频）：
```json
{
  "type": "video",
  "title": "...", "thumbnail": "...", "duration": 123,
  "uploader": "...", "platform": "Bilibili",
  "options": [{
    "label": "1080P", "height": 1080,
    "selector": "bestvideo[height<=1080]+bestaudio/best[height<=1080]/best",
    "ext": "mp4", "direct_url": "https://... 或 null", "size_mb": 25.4
  }]
}
```
响应（播放列表）：`{"type": "playlist", "title": "...", "count": 12, "entries": [{"title","url","duration","thumbnail"}]}`（最多 50 条）

### POST /api/download
请求：`{"url": "...", "selector": "bestvideo[height<=720]+bestaudio/best", "title": "..."}`
响应：`{"task_id": "abc123..."}`

### GET /api/progress/{task_id}（SSE）
持续推送：`{"status": "downloading", "percent": 42.5, "speed": "1.2MiB/s", "eta": "00:10", ...}`
终态：`status = "completed" | "error"`

### GET /api/file/{task_id}
返回文件流（Content-Disposition 触发浏览器保存），发送后服务器删除文件与任务。

### 错误码
- 400 链接为空；404 文件/任务不存在；422 平台解析失败（含原因）；500 其他异常

**风控平台 cookies 方案（已落地）**：项目根目录放 `cookies.txt`（Netscape 格式）即自动生效（`base_opts()` 每次请求检测）。
一键刷新工具：`python tools/refresh_cookies.py [url]`——用本机 Chromium（agent-browser 的 chrome-154）真实访问目标站点，
导出包含 JS 写入字段（ttwid / s_v_web_id / odin_tt 等）的全套 cookies；cookie 过期后重跑一次即可。
注意：单纯调 ttwid 注册接口或 httpx 抓首页 set-cookie 都不够（字段不全，抖音仍拒绝），必须走真实浏览器。

## 7. 扩展点（给后续开发者的指引）

- **加数据库**：TASKS 字典替换为 SQLite（SQLModel/SQLAlchemy），先加 `users`、`download_records` 两表即可支撑 R2/R7
- **加批量下载**：前端把 playlist entries 批量提交 `/api/download`，后端目前已有线程模型可直接承受；量大再换任务队列
- **加视频总结**：新增 `/api/summary`：yt-dlp 下字幕（`writesubtitles`/`writeautomaticsub`）→ 送 LLM → 返回摘要。与下载主流程解耦
- **加支付**：先做 R2 账号体系，再对接微信支付 Native/JSAPI；`static/` 里的 VIP 弹窗已预留入口（`showVip()`）
- **限速/并发**：在 `_run_download` 的 opts 里加 `ratelimit`，或用信号量包裹下载线程
