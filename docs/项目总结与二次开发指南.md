# SnapVid 项目总结与二次开发指南

> 2026-10-04 整理｜面向二次开发：读完这份文档即可上手改代码。
> 更细的接口契约见《方案设计.md》，功能边界见《需求分析.md》。

## 1. 一句话理解这个项目

**一个 FastAPI 薄壳包住 yt-dlp**：前端把链接发给后端 → 后端用 yt-dlp 解析/下载 → 结果回传浏览器。
本身几乎不实现下载逻辑，所有平台兼容性都来自 yt-dlp（1000+ 站点）。

## 2. 代码地图（总共约 600 行，全部在这几个文件里）

| 文件 | 职责 | 二次开发时改它的场景 |
|---|---|---|
| `main.py` | 后端全部逻辑 | 加接口、改下载行为、接数据库 |
| `static/index.html` | 页面结构 | 加区块、改文案 |
| `static/style.css` | 样式（仿 painting 风格） | 换肤、调布局 |

| `启动.bat` | 一键启动 | 换端口、换 Python 路径 |

### main.py 内部结构（从上往下）
1. `base_opts()` — yt-dlp 全局配置（ffmpeg 路径、cookies.txt 自动加载）
2. `POST /api/parse` — 解析链接，返回元信息 + 清晰度选项（`build_options()` 从 formats 提取档位）
3. `POST /api/download` — 创建下载任务（内存字典 `TASKS` + 后台线程 `_run_download()`）
4. `GET /api/progress/{task_id}` — SSE 推送进度（前端 EventSource 接收）
5. `GET /api/file/{task_id}` — 回传文件，发送后删除（服务器零留存）
6. `_janitor()` — 每 10 分钟巡检清理超 1 小时的残留文件
7. 静态文件托管在 `/`

### app.js 内部结构
`doParse()` 解析 → `renderVideo()` 渲染清晰度卡片 → `downloadDirect()` 直链下载 / `downloadRelay()` 中转下载（SSE 监听进度，完成后跳转 `/api/file/`）。
VIP 拦截逻辑在 `FREE_MAX_HEIGHT = 720` 一个常量控制。

## 3. 关键设计决策（改代码前必读，避免踩坑）

1. **清晰度用 selector 表达式**，不用 format_id：`bestvideo[height<=H]+bestaudio/best[height<=H]/best`。B站等平台 format_id 会变，表达式稳定。**裸 `best[height<=H]` 在纯 DASH 站点会报错，别用。**
2. **cookies.txt 放项目根目录自动生效**（`base_opts()` 每次请求检测），绝不入库（.gitignore 已排除，里面有登录态）。
3. **解析和下载分离**：parse 只取元信息；download 才拉流。不要合并成一个接口。
4. **无数据库**：任务状态全在内存 `TASKS` 字典，重启清零。这是刻意的轻量设计。
5. **ffmpeg 来自 imageio-ffmpeg**（pip 包自带二进制），别假设系统装了 ffmpeg。
6. **yt-dlp 永不改源码**：平台失效就 `pip install -U yt-dlp`。

## 4. 已踩过的坑（验数结论）

| 坑 | 结论 |
|---|---|
| 抖音分享文案整段粘贴 | 已解决：`extract_url()` 前后端各一份，自动提取链接 |
| 抖音风控要 fresh cookies | 只有真实浏览器能拿全字段（ttwid 等），用 `tools/refresh_cookies.py` 刷新 |
| B站无合一直链 | DASH 音视频分离，direct_url 为 null 属预期，走中转 |
| GitHub SSH 22 端口被封 | 本机网络封 22，用 HTTPS + Git 凭据管理器（已配好） |

## 5. 二次开发路线图（按推荐顺序）

### R1 批量下载（改动最小，建议先做）
- 前端：`renderPlaylist()` 里加"全部下载"按钮，循环调 `POST /api/download`
- 后端：现成可用，线程模型直接承受；量大再加信号量限并发

### R2 账号体系（VIP 落地的前置）
- 加 SQLite：`users` 表（id/账号/密码哈希/vip等级/到期时间）
- FastAPI 加 `Depends` 鉴权；前端 `FREE_MAX_HEIGHT` 改为从后端用户信息读取
- 下载接口记录 `download_records` 表，实现"免费每日 3 次"

### R3 支付
- 依赖 R2。对接微信支付 Native（扫码），回调里更新 users.vip 字段
- 前端 VIP 弹窗 `showVip()` 已预留，把 `alert` 换成真实下单逻辑

### R4 视频总结 / R5 字幕翻译
- 新接口 `/api/summary`：yt-dlp 加 `writesubtitles: True` 下字幕 → 送 LLM → 返回摘要
- 与下载主流程完全解耦，独立开发

### R6 Cookies 管理页
- 依赖 R2。用户上传自己的 cookies.txt 存到用户目录，`base_opts()` 按用户切换
